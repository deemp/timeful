## Important Decisions

- **Feature goal**: on the timed grid, hovering or clicking an inactive (non-selectable) cell must make the Responses sidebar header show `(0/N)` (N = number of respondents) and strike through every respondent row (`tw-line-through`), regardless of where the pointer came from (an active cell, outside the grid, or another inactive cell). Status-square coloring is explicitly out of scope (separate inbox item in `frontend/backlog/inbox.md`).
- **Naming**: use `curTimeslotInactive` (not `curTimeslotUnavailable`). "Unavailable" is overloaded with the respondents' per-slot `curTimeslotAvailability`; "inactive" matches existing terms (`isSelectableSlot`, "inactive grey cells", "inactive specific-time gaps").
- **Design**: keep the documented invariant that `curTimeslot` never points at an inactive cell (existing test `useAvailabilityData.test.ts:290` "does not move the read-only cursor onto inactive or disabled cells" must stay green). The grid cursor is already kept off inactive cells via `clearSelectedSlot` → `avail.resetCurTimeslot()` (`{-1,-1}`), which also clears the grid highlight; grid rendering already never highlights disabled cells (`!isDisabled` guard at `scheduleOverlapRendering.ts:353`). Therefore the panel needs a separate boolean state: `curTimeslotInactive`.
- **State machine** (new ref `curTimeslotInactive = ref(false)` in `useAvailabilityData`):
  - `showAvailability` on a valid cell → populate `curTimeslotAvailability` per respondent, set `curTimeslot = {row, col}`, set `curTimeslotInactive = false`.
  - `showAvailability` on a null-date cell → set every current respondent's `curTimeslotAvailability[id] = false`, set `curTimeslotInactive = true`, do NOT touch `curTimeslot`.
  - Deselect path (`ui.resetCurTimeslot` in `useScheduleOverlapUI.ts`, called by `deselectRespondents`) → set `curTimeslotInactive = false` so the header returns to `(N)`.
- **Panel "selected" logic** (`useRespondentsListState.ts`): `isCurTimeslotSelected = computed(() => opts.curDate.value != null || opts.curTimeslotInactive.value)`; `respondentIfNeeded` must early-return when `curTimeslotInactive` is true (prevents stale "if needed" stars from the previously hovered active cell's `curDate`). Strikethrough comes for free via existing `respondentClass` (`!curTimeslotAvailability[id]` → `tw-line-through`).
- Scope: timed grid + shared handlers only; do not change days-only grid behavior; keep `useTimedGridInteractions` untouched (its `clearSelectedSlot`/`showAvailability` wiring already flows through the new logic).
