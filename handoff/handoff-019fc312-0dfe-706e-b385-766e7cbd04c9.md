## Findings And Risks

- `aB3BE` is a canonical timed event in `Asia/Baghdad` on 2026-08-06 and 2026-08-07, with enabled/active 15-minute slots from `09:00` through `17:00` local time.
- In GMT+3:30, the real projected interval is `09:30-17:30`. `frontend/src/composables/schedule_overlap/useCalendarGrid.ts` floors the start and ceils the end at lines 424-425, producing `09:00-18:00` rows. The extra rows have no enabled slot and render as gray unavailable padding.
- In GMT+12, the real projected interval for each event day is `18:00-02:00` across two local dates. `useCalendarGrid.ts:427-437` deliberately splits the time range; `frontend/src/components/schedule_overlap/ScheduleOverlap.vue:1167-1173` inserts a `split-gap` row. Existing tests currently assert this behavior.
- Canonical timed columns are built from projected event-start seeds at `useCalendarGrid.ts:578-592`, not every projected enabled-slot date. For GMT+12 this omits the final next-date column needed for the Aug 7 event's Aug 8 `00:00-02:00` slots.
- `ScheduleOverlap.vue:747-812` creates filler for one shared page time axis, not independently per display-date column.
- `useCalendarGrid.ts:497-501` adds `dayOffset` when formatting headers even though the canonical path has already created display-timezone day objects; this can make header dates disagree with cell ownership in shifted timezones.
