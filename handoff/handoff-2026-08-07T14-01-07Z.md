## Important Decisions

- A "corresponding timeslot" = the currently hovered/clicked grid cell, represented by `curDate` (panel view model derives it from `getDateFromRowCol(curTimeslot.row, curTimeslot.col)`, `useScheduleOverlapViewModels.ts:257`).
- Behaviour matrix (agreed with the user):
  - No slot in context (`curDate == null` and `curTimeslotInactive == false`: outside grid, split-gap, collapsed-row-mouseleave) -> keep the existing generic profile icon.
  - Active slot hovered/clicked (`curDate != null`) -> legend square per respondent: green `#00994C77` (available), yellow (if needed), pink `#F9CCCC` (unavailable).
  - Inactive/disabled cell inside the grid hovered (`curTimeslotInactive == true`) -> **grey square** (user explicitly chose "Show grey squares" over "profile icons" for this case, matching `inbox.md:370`).
- Grey distinction uses `getTimedCellState()` (`useCalendarGrid.ts:1066`): `"enabled_inactive"` -> light-gray-stroke `#DFDFDF` (legend "Disabled, change in Edit event"), anything else -> gray `#BDBDBD`/`tw-bg-gray` (legend "Disabled, outside the event dates in the event timezone").
- Status precedence mirrors the CSV export (`useRespondentsCsvExport.ts:68-73`): availability-set hit = available; else `ifNeeded` hit = if needed; else unavailable.
- Use literal Tailwind class strings (static map) so the JIT keeps them; reuse the exact legend classes from `ColorLegend.vue`.
- Keep the existing hover-to-select checkbox feature untouched (`respondent-control__checkbox` swaps over the avatar/status square on row hover).
